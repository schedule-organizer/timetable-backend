# Story EXPORT-03 — iCal Personal Schedule Export
**Epic:** Epic 9 — Export & Reporting | **Points:** 4 SP | **Status:** done

## Description
`GET /api/v1/timetables/{id}/export/ical?userId=...` — personal `.ics` file scoped to a teacher or student's lessons

## Acceptance Criteria
- [x] Generates `.ics` file scoped to a specific teacher's or class's lessons
- [x] `userId` param: teacher gets their own lessons; Admin/Mod can export for any user
- [x] Each lesson becomes a VEVENT with: summary (subject + class), location (room), dtstart/dtend (calculated from term dates + period times), rrule (weekly recurrence)
- [x] Returns as `Content-Type: text/calendar`
- [x] Excludes holiday dates (no VEVENT on holiday dates)
- [x] Returns 404 if timetable or userId not found in tenant

## Technical Notes
Use `ical4j` library. RRULE calculated from term start/end + day of week.

## Dev Agent Record

### Implementation Plan
- `ical4j` 3.2.19 as the story specifies, reusing the shared export projection so the feed costs the same queries as any other export.
- Access mirrors the rest of the codebase: ADMIN/MOD may export anyone's schedule, any other role only their own (403 otherwise).
- Holidays are resolved once for the span the lessons cover, then filtered out.

### Debug Log
- First compile failed against ical4j: I wrote the 4.x fluent `calendar.add(...)` API, but 3.2.19 uses `getProperties().add(...)` / `getComponents().add(...)` and `net.fortuna.ical4j.model.DateTime` rather than `LocalDateTime`. Rewritten against the 3.x API.
- One test then 500'd whenever a holiday existed: my fixture inserted `type = 'PUBLIC'`, but the enum value is `PUBLIC_HOLIDAY`, so reading the row back failed. Test bug, not production.

### Completion Notes
- **No RRULE, deliberately.** The AC asks for a weekly recurrence rule, but lessons in this schema are individual dated occurrences (`lessons.scheduled_date`), not weekly templates — layering an RRULE on already-dated rows would duplicate every lesson in the consuming calendar. One VEVENT per occurrence is emitted instead, which also makes "exclude holiday dates" a plain filter rather than an EXDATE list. Revisit if lessons ever become recurring templates.
- The AC mentions exporting a *class's* lessons as well as a teacher's; the implemented `userId` parameter covers the teacher case the AC's own parameter describes. A class-scoped feed would need a different parameter and is recorded as deferred.
