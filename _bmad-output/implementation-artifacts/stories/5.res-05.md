# Story RES-05 — Teacher Qualifications
**Epic:** Epic 5 — Resource Management | **Points:** 2 SP | **Status:** done

## Description
`POST/DELETE /api/v1/teachers/{id}/qualifications` — add/remove subject qualifications with optional periods-per-cycle allocation

## Acceptance Criteria
- [x] `POST` adds a qualification (subjectId, periodsPerCycle optional)
- [x] `DELETE /api/v1/teachers/{id}/qualifications/{qualId}` removes a qualification
- [x] Returns 404 if teacher or subject not found in tenant
- [x] Returns 409 if qualification for that subject already exists
- [x] `GET /api/v1/teachers/{id}/qualifications` lists all qualifications for a teacher
- [x] Solver uses qualifications to restrict teacher-subject assignments

## Technical Notes
`teacher_qualifications` junction table.

## Tasks / Subtasks
- [x] Flyway `V017__create_teacher_qualifications.sql` (tenant, teacher, subject; UNIQUE tenant+teacher+subject; optional `periods_per_cycle`)
- [x] Domain `TeacherQualification`, `TeacherQualificationRepository`, DTOs, `TeacherQualificationService`, `TeacherQualificationController`
- [x] Unit tests `TeacherQualificationServiceTest`; API tests `TeacherQualificationEndpointTest`
- [x] Solver: `TeacherSubjectQualification` fact, `Lesson` teacherUserId+subjectId, `TimetableSolution` facts list, hard constraint in `SchediFlowConstraintProvider`, `TeacherQualificationConstraintSolverTest`

## Dev Agent Record

### Implementation Plan
- Mirrored teacher write policy: POST/DELETE ADMIN/MOD; GET any authenticated user.
- Teacher and subject resolved with same active-entity rules as RES-04/RES-03; duplicate `(tenant, teacher, subject)` → 409; unique race → `DataIntegrityViolationException` mapped to 409.
- DELETE resolves qualification by `(qualificationId, teacherId, tenant)` so another teacher’s id returns 404.
- Timefold: lessons with both `teacherUserId` and `subjectId` require a matching `TeacherSubjectQualification` problem fact; lessons without those fields unchanged for existing holiday tests.
