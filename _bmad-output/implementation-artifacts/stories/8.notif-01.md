# Story NOTIF-01 — WebSocket Infrastructure
**Epic:** Epic 8 — Notifications | **Points:** 4 SP | **Status:** done

## Description
`WebSocketEventPublisher` — typed event publisher for all STOMP topics; `WebSocketConfig` with SockJS fallback at `ws://{host}/ws`

## Acceptance Criteria
- [x] `WebSocketConfig` configures STOMP over WebSocket at `/ws` endpoint with SockJS fallback
- [x] Message broker configured for `/topic` (broadcast) and `/queue` (personal) channels
- [x] `WebSocketEventPublisher` provides typed `publish(topic, payload)` method
- [x] JWT authentication validated on STOMP CONNECT (via `ChannelInterceptor`)
- [x] Connection rejected with 401 if JWT invalid or missing
- [x] Tenant ID extracted from JWT and stored in STOMP session for scoping

## Technical Notes
Spring WebSocket + STOMP. `SimpMessagingTemplate` wrapped in `WebSocketEventPublisher`. Security via `ChannelInterceptor`.

## Dev Agent Record

### Implementation Plan
- **Most of this story was already built.** COVER-07 created `WebSocketConfig`, `StompAuthChannelInterceptor`, `WebSocketDestinations` and `WebSocketEventPublisher` because Epic 8 was still `backlog` and COVER-01/04 needed events; SCHED-06 and SCHED-12 then added two more topic families and their tenant checks. Five of the six ACs were already satisfied and verified by existing tests.
- **The genuine gap was SockJS fallback.** `/ws` is now registered twice — natively, and again `.withSockJS()`. Registering only the SockJS variant would have broken native clients, which is what `CoverWebSocketIntegrationTest` uses; both are asserted.
- Tenant and user ids are now also written to STOMP **session attributes** on CONNECT. The principal already carried them, but the AC asks for them on the session, and it lets anything reading session attributes scope without unwrapping the authentication.

### Debug Log
- `aSockJsClientCanConnectAndSubscribe` first failed with `ConnectionLostException`. The test used `connectAsync(url, handler, uriVars...)`, so the `StompHeaders` went in as a URI variable and the CONNECT frame carried no token — the server was right to reject it. Switched to the full overload.

### Completion Notes
- Nothing was rebuilt. `deferred-work.md` had flagged that NOTIF-01 should adopt this stack rather than duplicate it; a second STOMP configuration would have conflicted with five stories' worth of behaviour.
- Tests: `SockJsFallbackIntegrationTest` (2); `CoverWebSocketIntegrationTest` (8) and `StompAuthChannelInterceptorTest` (17) continue to cover CONNECT auth, rejection and per-subscription scoping.
