## Technical Notes
`audit_log` table. AOP advice captures method name, args (sanitised), actor from SecurityContext.

## Dev Agent Record

### Implementation Plan
- `@Audited(action, entityType)` on a service method; `AuditAspect` records it with an `@Around` advice. Three constraints, because this wraps business methods:
  - The target runs **first** and its result is returned untouched, so auditing can never alter behaviour.
  - Only **successful** calls are recorded — a rejected attempt did not happen to the data, and logging failures would fill the trail with validation noise.
  - A failure to write is logged and swallowed. An audit entry is worth less than the operation it describes and must never turn a success into an error.
- Arguments are **summarised, never serialised**: numbers and short strings by value, everything else by type name only. A request object appears as `TimetablePublishRequest`, so passwords and payloads cannot leak into the log.
- Entity id follows a stated convention — the first `Long` argument of the audited method.
- Every filter is optional in one query; `endDate` covers to the end of that day so a single-day filter returns that day.

### Completion Notes
- Applied to three high-value mutations so far: timetable publish, checkpoint restore, and draft deletion. The annotation is the extension point — adding coverage is one line per method, with no change to the aspect.
- Entries with no `TenantContext` are skipped rather than written tenant-less: a scheduled sweep is not a user action and has no tenant to file under.
- ADMIN only, not ADMIN/MOD — the trail shows what every user in the institution did.
- Tests: `AuditLogEndpointTest` (9), including that a rejected publish adds no entry and that details name the request by type rather than dumping it.
