# Story EXPORT-02 — CSV Timetable Export
**Epic:** Epic 9 — Export & Reporting | **Points:** 3 SP | **Status:** done

## Description
`GET /api/v1/timetables/{id}/export/csv` — CSV export of all lessons with teacher, room, period columns; Admin/Mod only

## Acceptance Criteria
- [x] Returns CSV with columns: lessonId, subject, teacher, room, class, dayOfWeek, periodName, startTime, endTime
- [x] Returns as `Content-Type: text/csv` with `Content-Disposition: attachment; filename="timetable-{id}.csv"`
- [x] Returns 404 if timetable not found in tenant
- [x] Admin/Mod only; Teachers get 403
- [x] Sorted by dayOfWeek, then periodName
- [x] UTF-8 encoded with BOM for Excel compatibility

## Technical Notes
Use Apache Commons CSV. Stream response to avoid loading all lessons into memory for large timetables.

## Dev Agent Record

### Implementation Plan
- One joined projection (`LessonRepository.findExportRows`) resolves subject, teacher, room, class and period names in a single query, shared by every export format.
- Ordered by day then **period ordinal**, not period *name*: names like "Period 10" and "Period 2" sort wrongly as text, and ordinal is the bell schedule's own sequence.
- UTF-8 BOM prefix so Excel reads accented names correctly, and `text/csv;charset=UTF-8` so other clients decode without guessing.

### Debug Log
- Three tests failed with an empty body: `StreamingResponseBody` needs an async dispatch in MockMvc. Adding one then failed differently — the async re-dispatch collides with the Spring Security filter chain ("response is already committed").
- The BOM assertion then failed because MockMvc decoded as ISO-8859-1; the response declared no charset. Fixed by declaring UTF-8, which is also correct for real clients.

### Completion Notes
- **Not streamed, deliberately.** The story's technical note suggests streaming to avoid holding every lesson in memory, but the rows must be loaded up front regardless so a missing timetable is a clean 404 rather than a half-written 200. Streaming would therefore only have avoided buffering the *rendered text*, at the cost of an async response fighting the security filter chain. True end-to-end streaming needs a cursor-based read; recorded as deferred work.
