# Story AUTH-04 — Logout
**Epic:** Epic 2 — Authentication & User Management | **Points:** 1 SP | **Status:** Done

## Description
`POST /api/v1/auth/logout` — invalidates (deletes) refresh token server-side

## Acceptance Criteria
- [x] Deletes refresh token record from DB
- [x] Clears the HttpOnly refresh cookie (Set-Cookie with expired date)
- [x] Returns 204 even if no refresh token cookie present (idempotent)
- [x] Requires valid JWT access token (authenticated endpoint)

## Technical Notes
No body required. Cookie cleared by setting max-age=0.

## Tasks / Subtasks

- [x] T1: Update SecurityConfig — replace blanket `/api/v1/auth/**` permitAll with explicit public paths; logout falls through to `anyRequest().authenticated()`
- [x] T2: Add `void deleteByToken(String token)` to RefreshTokenRepository
- [x] T3: Add `logout()` to AuthService — calls `deleteByToken` if token present (idempotent: no-op if already gone)
- [x] T4: Add `POST /api/v1/auth/logout` to AuthController — `@CookieValue(required=false)`, clears cookie (max-age=0), returns 204 No Content
- [x] T5: Unit tests (2): logout with token deletes it; logout without token is no-op
- [x] T6: Integration tests (4): logout with JWT + cookie → 204 + cleared cookie; without cookie → 204; called twice → 204; without JWT → 401

## Dev Agent Record

### Implementation Plan
- SecurityConfig updated to list each public `/auth/` path explicitly; logout relies on `anyRequest().authenticated()`
- `deleteByToken` is a Spring Data derived delete — single query, no `findByToken` round-trip needed
- Cookie cleared by `ResponseCookie.from("refresh_token", "").maxAge(0).path(...).httpOnly(true).sameSite("Strict").build()`
- 204 No Content (no response body needed for logout)

### Debug Log
- SecurityConfig originally permitted all `/api/v1/auth/**`; logout requires auth so the blanket rule was replaced with explicit per-path matchers for the four public endpoints.
