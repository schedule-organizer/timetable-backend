# Story AUTH-02 — Email/Password Login
**Epic:** Epic 2 — Authentication & User Management | **Points:** 3 SP | **Status:** Done

## Description
`POST /api/v1/auth/login` — email/password login, returns JWT access token (15 min) + `HttpOnly` refresh cookie (7 days)

## Acceptance Criteria
- [x] Endpoint accepts: email, password
- [x] Returns JWT access token (15 min expiry) in response body
- [x] Sets `HttpOnly`, `Secure`, `SameSite=Strict` refresh token cookie (7 days)
- [x] Returns 401 for invalid credentials (no distinction between wrong email vs password)
- [x] Returns 401 for INACTIVE user accounts
- [x] Rate limited: 10 req/min/IP on `/auth/**`

## Technical Notes
Refresh token stored in `refresh_tokens` table. BCrypt comparison with cost factor 12.

## Dev Agent Record

### Implementation Plan
- `UnauthorizedException` gives no hint whether the email or password was wrong (AC: no distinction)
- Old refresh tokens deleted before creating new one (`deleteByUserId`) — prevents accumulation
- `ResponseCookie` used for SameSite=Strict; jakarta.servlet.Cookie doesn't support SameSite natively
- Rate limiter: `ConcurrentHashMap<String, Deque<Long>>` sliding window; configurable `max-requests` and `window-ms` for test overrides
- Rate limit response is written directly as JSON (interceptor runs before controllers)

### Debug Log
- `@DirtiesContext` resets the Spring context but H2 `DB_CLOSE_DELAY=-1` persists data across context restarts. Fixed by generating a UUID-based email in `@BeforeEach` so each test's registration never conflicts with prior test data.
- Rate limit test initially miscounted: `@BeforeEach` register also hits `/api/v1/auth/**` and consumes one rate-limit slot. Fixed by using `max-requests=4` (test property) so 1 register + 3 ok logins + 1 rejected = correct 429.
- `jakarta.servlet.http.Cookie` has no `setSameSite()`. Switched `addRefreshCookie` to `ResponseCookie` (Spring) which serialises the full `Set-Cookie` header including `SameSite=Strict`.

### Completion Notes
✅ All 6 Acceptance Criteria satisfied.
✅ 35 tests pass (8 login integration, 8 register integration, 14 unit, 5 existing regression) — 0 failures, 0 errors.
- `POST /api/v1/auth/login` verifies credentials with BCrypt, checks ACTIVE status, rotates refresh token.
