# Story SCHED-10 — Atomic Lesson Swap
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 3 SP | **Status:** done

## Description
`POST /api/v1/lessons/{id}/swap` — atomic swap of two lesson cards with conflict validation on both sides

## Acceptance Criteria
- [x] Accepts: `targetLessonId` in request body
- [x] Validates no conflicts for both lessons in their swapped positions before committing
- [x] Atomically swaps period and room assignments for both lessons
- [x] Returns both updated lessons with their `hasConflict` flags
- [x] Returns 400 if swap would create conflicts on either side
- [x] Broadcasts `LESSON_UPDATED` event for both lessons (SCHED-12)
- [x] Returns 404 if either lesson not found in tenant

## Technical Notes
Single DB transaction for both updates. Conflict check runs pre-commit on both sides.

## Dev Agent Record

### Implementation Plan
- **A swap refuses on conflict, unlike a move.** A move is a deliberate drag where a temporary clash is acceptable; a swap is a convenience that touches two lessons at once, and silently degrading both is worse than refusing. 400 with nothing written.
- Both sides are validated before either is written, inside one transaction.
- Each side's check would otherwise see the *other* still sitting in the slot it is about to vacate, so violations naming the counterpart are dropped. Without that, no two lessons of the same class could ever swap — covered by `swap_ignoresTheCounterpartsOwnOldPosition`.
- Swapping a lesson with itself is a 400 rather than a silent no-op.

### Debug Log
- `swap_thatWouldConflict_returns400AndChangesNothing` first failed 200. The fault was the test, not the service: the chosen target sat in a period that created no clash. Rebuilt the scenario so the swap genuinely double-books a teacher, and added the counterpart-exclusion case above.

### Completion Notes
- Period *and* room are exchanged together, since swapping one without the other would leave two cards in an incoherent state.
- Tests: covered by `LessonMutationEndpointTest`.
