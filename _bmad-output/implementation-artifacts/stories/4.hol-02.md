# Story HOL-02 — Public Holiday Import
**Epic:** Epic 4 — Holiday & Vacation Calendar | **Points:** 5 SP | **Status:** done

## Description
`POST /api/v1/holidays/import` — fetch public holiday dates from external feed (Calendarific free tier, TD-06) by country/region; persist as `holiday_dates`; idempotent on re-import

## Acceptance Criteria
- [x] Accepts: calendarId, country code, region (optional), year
- [x] Fetches holidays from Calendarific API
- [x] Persists returned dates as `holiday_dates` with type `PUBLIC_HOLIDAY`
- [x] Idempotent: re-importing same country/year updates existing records, does not duplicate
- [x] Returns count of imported/updated/skipped dates
- [x] Returns 502 if Calendarific API is unreachable (with user-friendly error)
- [x] Calendarific API key configured via environment variable

## Technical Notes
HTTP client with timeout (5s). Wrap Calendarific client in `HolidayFeedClient` interface for testability.

### Completion Notes
- **Endpoint:** `POST /api/v1/holidays/import` with body `{ calendarId, country, region?, year }`. Country normalized to uppercase for Calendarific.
- **Feed:** National holidays only (`type=national`). Optional `location` query when `region` is set. Multiple feed rows on the same calendar date are merged into one name string before persistence.
- **Idempotency:** Unique `(holiday_calendar_id, date)`; same name + `PUBLIC_HOLIDAY` → skipped; name or type change → updated.
- **502:** `SchediFlowException` via `BadGatewayException`; missing API key → 400 `BAD_REQUEST`.

### Review Findings

**Patch:**
- [x] [Review][Patch] API key exposed in logged outbound URI — add a `ClientHttpRequestInterceptor` on `calendarificRestClient` that redacts `api_key=…` from any logged request URI. [`CalendarificClientConfig.java`]
- [x] [Review][Patch] `date.iso` datetime format silently drops holidays — Calendarific may return `"2026-01-01T00:00:00+05:30"` instead of `"2026-01-01"`; `LocalDate.parse(iso)` throws `DateTimeParseException` and skips the row. Fix: extract first 10 chars or use `OffsetDateTime.parse(...).toLocalDate()` as fallback. [`CalendarificHolidayFeedClient.java`]
- [x] [Review][Patch] `mergeByDate` + `truncateName` breaks re-import idempotency — merged name (e.g. `"A / B"`) may exceed 100 chars; next import sees a different truncated string, counts as `updated` every run. Fix: apply `truncateName` inside `mergeByDate` or in the merge lambda so the stored and incoming values are always compared post-truncation. [`CalendarificHolidayFeedClient.java` / `HolidayImportService.java`]
- [x] [Review][Patch] `DataIntegrityViolationException` on concurrent imports returns 500 — two simultaneous imports for the same calendar/year will both attempt insert, second hits the V009 unique index and throws an uncaught exception. Fix: catch `DataIntegrityViolationException` and treat as a skip (idempotent). [`HolidayImportService.java`]
- [x] [Review][Patch] `country` missing `@Pattern` — `@Size(min=2, max=2)` allows `"12"` or `"!!"`, which Calendarific rejects with a non-200 meta code, surfacing as 502 instead of 400. Fix: add `@Pattern(regexp="[A-Za-z]{2}")`. [`HolidayImportRequest.java`]
- [x] [Review][Patch] Empty `CALENDARIFIC_API_KEY` not validated at startup — blank key is only detected at first request. Fix: add `@PostConstruct` check or use `@ConfigurationProperties` with `@NotBlank` to fail fast on startup. [`CalendarificClientConfig.java`]
- [x] [Review][Patch] `truncateName` splits Unicode surrogate pairs — `name.substring(0, 100)` truncates at char index, not code point; breaks supplementary-plane characters (emoji, rare CJK). Fix: use `name.codePointCount` and `name.offsetByCodePoints(0, 100)`. [`HolidayImportService.java`]
- [x] [Review][Patch] `CalendarificHolidayFeedClientTest` missing `RestClientException→502` and `meta.code!=200` paths — two of three main failure branches in `CalendarificHolidayFeedClient` are untested. [`CalendarificHolidayFeedClientTest.java`]
- [x] [Review][Patch] No endpoint test for missing API key → 400 response [`HolidayImportEndpointTest.java`]
- [x] [Review][Patch] Endpoint 502 test does not assert user-friendly message body — AC requires user-friendly error; only `$.code` is checked. [`HolidayImportEndpointTest.java`]
- [x] [Review][Patch] No test for `region` parameter forwarding to Calendarific [`HolidayImportEndpointTest.java`]
- [x] [Review][Patch] No `@Valid` boundary tests — no assertions for invalid `country` length, `year` out of `[1900,2100]`, null `calendarId`. [`HolidayImportEndpointTest.java`]

- [x] [Review][Defer] Empty holiday feed (200 with all zeros) indistinguishable from wrong config — deferred, design choice; caller can infer intent from context
