# Story RES-09 — Forbidden Slots
**Epic:** Epic 5 — Resource Management | **Points:** 3 SP | **Status:** done

## Description
`POST/DELETE /api/v1/forbidden-slots` — entity-type-agnostic forbidden slot creation for teachers, rooms, and classes; recurring and date-specific variants

## Acceptance Criteria
- [x] `POST` creates forbidden slot (entityType: TEACHER/ROOM/CLASS, entityId, dayOfWeek or specificDate, periodId, isRecurring)
- [x] `DELETE /api/v1/forbidden-slots/{id}` removes a forbidden slot
- [x] `GET /api/v1/forbidden-slots?entityType=&entityId=` lists slots for an entity
- [x] Returns 404 if entityId not found in tenant
- [x] Recurring slots apply every week; specific-date slots apply once
- [x] `V021__create_forbidden_slots.sql` Flyway migration included

## Dev Agent Record

### Implementation Plan
- Recurrence is validated both in the service (clear 400 messages) and by a DB CHECK, so a row can never hold both a weekday and a date, or neither.
- `entity_id` is polymorphic and therefore has no FK; the service dispatches on `entity_type` to the teacher / room / class repository and 404s if the entity is not active in the tenant.
- `periodId` is tenant-checked against `schedule_periods` and 404s otherwise.
- Access: ADMIN and MOD manage any entity. Any other role may only touch the TEACHER entity whose `user_id` is their own — this is what makes FR35 ("TEACHER marks forbidden slots") reachable. The check lives in the service rather than `@PreAuthorize` because it depends on the target row, and it raises `AccessDeniedException` so the existing handler renders the standard 403 envelope.

### Completion Notes
- Added one behaviour beyond the ACs: posting a slot identical to an existing one for the same entity (same period, same recurrence, same day/date) returns 409 rather than silently duplicating. Checked in Java over the entity's own slots rather than with a DB unique constraint, because `day_of_week` and `specific_date` are each NULL half the time and SQL unique indexes treat NULLs as distinct.
- `findAllForSolver(tenantId)` exposes the tenant's slots for SCHED-03 to turn into hard unavailability facts. No solver constraint is wired up in this story: the current `UnavailablePeriodPenalty` fact is keyed on a period slot alone with no entity, and the solver `Lesson` has no room or class reference, so entity-scoped unavailability cannot be expressed until SCHED-02/03 fills out the planning model. The ACs require no solver behaviour here.
- `./mvnw -o test -Dtest='ForbiddenSlotServiceTest'` → 20 passed; `-Dtest='ForbiddenSlotEndpointTest'` → 20 passed.
