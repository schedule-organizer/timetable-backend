# Story COVER-07 — Cover & Delegation WebSocket Events
**Epic:** Epic 7 — Cover, Delegation & Temporary Schedules | **Points:** 3 SP | **Status:** done

## Description
WebSocket: `COVER_ASSIGNED` event to `/topic/tenant/{tenantId}/notifications`; `DELEGATION_UPDATE` event to requesting and receiving teacher queues

## Acceptance Criteria
- [x] `COVER_ASSIGNED` event: `{ lessonId, coverTeacherId, originalTeacherId, assignedAt }` → `/topic/tenant/{tenantId}/notifications`
- [x] `DELEGATION_UPDATE` event: `{ requestId, type, status, lessonIds[] }` → personal queues for both requesting and target teachers
- [x] Personal queue format: `/queue/user/{userId}/notifications`
- [x] Events scoped to tenant
- [x] WebSocket subscription requires valid JWT

## Technical Notes
Depends on NOTIF-01 (`WebSocketEventPublisher`). Personal queues via STOMP user destinations.

## Dev Agent Record

### Implementation Plan
- **Built first, ahead of COVER-01…06**, because COVER-01 and COVER-04 both have ACs requiring these events. Retrofitting them afterwards would have meant either landing those stories with unmet ACs or reworking them.
- **NOTIF-01 does not exist** (Epic 8 is `backlog`), so the `WebSocketEventPublisher` this story "depends on" was built here. COVER-07's ACs already pin the contract — destination formats, tenant scoping, JWT on subscribe — so NOTIF-01 can adopt this publisher rather than the reverse.
- Authentication is on the STOMP CONNECT frame, not the HTTP handshake: browsers cannot set an `Authorization` header on a WebSocket upgrade, so `/ws/**` is permitted at the HTTP layer and the interceptor is the real gate.
- Publishing is best-effort — a broker failure is logged and swallowed, so a cover assignment is never rolled back because its notification could not be delivered.

### Debug Log
- `connectWithoutTokenIsRejected` / `connectWithInvalidTokenIsRejected` initially asserted on the server-side failure message. The server closes the socket instead of replying with a reason, so the client only observes `ConnectionLostException`. Assertions changed to verify no session is established; not leaking the reason to an unauthenticated client is the desirable behaviour.

### Completion Notes
- **Deviation from the technical note, deliberate.** The note suggests "personal queues via STOMP user destinations" (`convertAndSendToUser` → `/user/{session}/queue/...`), but the AC fixes the wire format as `/queue/user/{userId}/notifications`. The literal destination wins, since it is the testable, client-visible contract.
- That choice has a security consequence the ACs do not mention: under the simple broker, `/queue/**` is an ordinary destination, so without a check any authenticated user could subscribe to `/queue/user/{someoneElse}/notifications`, or to another tenant's topic. `StompAuthChannelInterceptor` therefore authorizes every SUBSCRIBE against the caller's own tenant and user id, and rejects unknown destinations outright. This is what makes "events scoped to tenant" true rather than merely conventional.
- The event discriminator field is named `event`, not `type`, because `DELEGATION_UPDATE`'s own payload already defines `type` as the delegation type (SWAP / HANDOVER).
- `./mvnw -o test -Dtest='StompAuthChannelInterceptorTest,WebSocketEventPublisherTest,WebSocketDestinationsTest'` → 23 passed; `-Dtest='CoverWebSocketIntegrationTest'` → 8 passed.
