# Story TMPL-04 — Save Custom Template
**Epic:** Epic 10 — Setup Templates (Post-MVP) | **Points:** 3 SP | **Status:** done

## Description
`POST /api/v1/templates` — save current institution configuration as a reusable custom template

## Acceptance Criteria
- [x] Accepts: name, description
- [x] Captures current tenant's: active bell schedule, settings, terminology, constraint defaults
- [x] Saves as custom template scoped to tenant (`is_built_in = false`)
- [x] Returns created template with id
- [x] Custom templates visible in `GET /api/v1/templates` alongside built-ins
- [x] Admin only
- [x] Max 10 custom templates per tenant (returns 400 if limit reached)

## Technical Notes
Snapshot of current config at time of save. Changes after save do not affect the template.

## Dev Agent Record

### Implementation Plan
- Snapshots the tenant's **default** bell schedule plus the settings, terminology and constraint defaults from tenant settings, into the same JSON shape the built-ins use — so a saved template applies through exactly the same path as a shipped one.
- The limit is `app.templates.max-custom` (default 10, as the AC specifies) and returns 400 when reached.

### Completion Notes
- A snapshot, as the technical note requires: later configuration changes do not alter a saved template.
- Custom templates are scoped to their tenant and invisible to others — asserted directly, since the entity is not tenant-filtered and that isolation therefore rests on the repository query rather than on Hibernate.
- `institutionType` defaults to `CUSTOM` when the caller does not supply one.
- Tests: covered by `TemplateEndpointTest`, including the limit boundary and cross-tenant invisibility.
