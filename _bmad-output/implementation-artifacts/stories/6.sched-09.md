# Story SCHED-09 — Pin/Unpin Lesson
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 2 SP | **Status:** done

## Description
`POST/DELETE /api/v1/lessons/{id}/pin` — pin/unpin a lesson card; pinned cards excluded from solver via `@PinningFilter`

## Acceptance Criteria
- [x] `POST /api/v1/lessons/{id}/pin` sets `isPinned=true`
- [x] `DELETE /api/v1/lessons/{id}/pin` sets `isPinned=false`
- [x] Pinned lessons excluded from solver re-scheduling via Timefold `@PinningFilter`
- [x] Returns 404 if lesson not found in tenant
- [x] Broadcasts `LESSON_UPDATED` WebSocket event (SCHED-12)
- [x] All roles can pin/unpin (teachers can pin their own lessons)

## Technical Notes
Timefold `@PinningFilter` reads `isPinned` flag. No conflict check needed on pin/unpin alone.

## Dev Agent Record

### Implementation Plan
- `POST/DELETE /api/v1/lessons/{id}/pin` toggling the `is_pinned` column from V027.
- Pinning does not move anything, so no conflict check gates it; the response still reports the lesson's existing conflict state so the caller's card stays accurate.
- All roles may pin their own lessons, per the AC; ADMIN/MOD may pin any.

### Completion Notes
- **The Timefold `@PinningFilter` is not wired yet.** The flag is persisted and exposed, but nothing builds a `TimetableSolution` from the database until SCHED-03. That story must read `is_pinned` when assembling the problem, or pinned lessons will still be moved by a solve. Recorded in `deferred-work.md`.
- Tests: covered by `LessonMutationEndpointTest`.
