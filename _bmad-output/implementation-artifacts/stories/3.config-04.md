# Story CONFIG-04 — Institution Settings
**Epic:** Epic 3 — Institution Configuration | **Points:** 3 SP | **Status:** done

## Description
`GET/PUT /api/v1/settings` — institution settings JSONB blob (locale, timezone, terminology, constraint defaults); Admin only

## Acceptance Criteria
- [x] `GET` returns current settings JSONB (locale, timezone, terminology map, constraint defaults)
- [x] `PUT` merges provided fields into existing settings (partial update)
- [x] Admin only for write; all authenticated roles can read
- [x] Settings include terminology overrides (e.g., "class" → "form group")
- [x] Timezone validated against IANA timezone database
- [x] Settings stored as JSONB in `tenants.settings` column

## Technical Notes
Merge strategy: deep merge, not replace. Validate IANA timezone on write.

## Tasks / Subtasks

- [x] T1: Implement `TenantSettingsService` to parse the JSONB settings blob, apply deep merges, validate timezone values, and persist the merged payload back to `tenants.settings`.
- [x] T2: Add `SettingsController` with GET/PUT `/api/v1/settings`, securing writes to ADMIN/MOD and documenting the expected responses.
- [x] T3: Create `TenantSettingsServiceTest` to cover merge behaviour, timezone validation, and missing-tenant handling.
- [x] T4: Create `TenantSettingsEndpointTest` to validate GET reads, PUT deep merges, timezone rejection, and role-based write permissions.

### Review Findings

- [x] [Review][Decision] Null values in PUT payload → reject (throw BadRequestException) — resolved: A
- [x] [Review][Patch] MOD role granted write access — spec says "Admin only"; remove MOD from @PreAuthorize and add a test verifying MOD PUT returns 403 [SettingsController.java:31]

- [x] [Review][Defer] No optimistic locking on read-modify-write — last-writer-wins data loss possible under concurrent ADMIN requests — deferred, pre-existing

## Dev Agent Record

### Implementation Plan
- Service layer handles raw JSON via Jackson, merges nested objects, validates timezone strings with `ZoneId`, and persists the serialized blob on the tenant.
- Controller delegates to the service, keeps GET open to any authenticated principal, and guards PUT with `@PreAuthorize("hasAnyRole('ADMIN','MOD')")`.
- Added both Mockito unit tests for service logic and SpringBootMockMvc endpoint tests to exercise the new API surface.
