# Story NOTIF-03 — Transactional Email Service
**Epic:** Epic 8 — Notifications | **Points:** 4 SP | **Status:** done

## Description
`SmtpEmailService` (via MailHog for MVP): transactional emails for teacher invite, cover assignment, delegation status change, and timetable published

## Acceptance Criteria
- [x] `SmtpEmailService` implements `EmailService` interface (for future SES swap)
- [x] Sends emails for: teacher invite (AUTH-05), cover assignment (COVER-01), delegation status change (COVER-04), timetable published (SCHED-07)
- [x] Email templates use Thymeleaf for HTML rendering
- [x] MailHog configured as SMTP server in `docker-compose.yml` (dev environment)
- [x] Failed sends logged and do not cause transaction rollback
- [x] `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` configured via environment variables

## Technical Notes
`@Async` email sending to avoid blocking request thread. Thymeleaf templates in `resources/templates/email/`.

## Dev Agent Record

### Implementation Plan
- `SmtpEmailService` implements the existing `EmailService` interface, which `StubEmailService` has satisfied since AUTH-05 — so swapping in SES later means one more implementation, not a caller change. The interface grew three methods for the cover, delegation and publication messages.
- Thymeleaf templates in `resources/templates/email/`; MailHog added to `docker-compose.yml` on 1025 (SMTP) and 8025 (UI).
- `@Async` on its own `emailExecutor` pool, so a slow SMTP server cannot starve anything else that later becomes asynchronous.
- **Every send failure is caught and logged.** Template errors as well as transport errors — a bounced notification must never fail, or roll back, the operation that triggered it.

### Debug Log
- Selecting the implementation by "is `spring.mail.host` set?" broke the Spring context: the property has an empty default, and `@ConditionalOnProperty` treats an empty value as *present*, so both `EmailService` beans activated and startup failed on a duplicate bean. Replaced with an explicit `app.mail.enabled` toggle (default false), which is unambiguous in both directions.

### Completion Notes
- Wired into all four flows the AC lists: invitation (AUTH-05, already existed), cover assignment (COVER-01), delegation decision (COVER-04, to both parties), timetable published (SCHED-07/NOTIF-02).
- `SMTP_HOST`, `SMTP_PORT` and `SMTP_FROM` are environment-driven; `MAIL_ENABLED` selects the implementation. Tests and offline development need no mail server.
- Tests: `SmtpEmailServiceTest` (6), covering each template plus swallowed transport and template failures.
