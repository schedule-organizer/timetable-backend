# Story COVER-02 — Cover Candidate Suggestions
**Epic:** Epic 7 — Cover, Delegation & Temporary Schedules | **Points:** 4 SP | **Status:** done

## Description
`GET /api/v1/cover/candidates?lessonId=...` — return qualified, available teachers sorted by workload gap; respects forbidden slots

## Acceptance Criteria
- [x] Returns list of teachers qualified for the lesson's subject
- [x] Filters out teachers with timetable conflicts in the lesson's period
- [x] Filters out teachers with forbidden slots for the lesson's period
- [x] Sorts by workload gap (available capacity - current assignments) descending
- [x] Returns: teacherId, displayName, qualifications, currentWorkload, workloadCap, workloadGap
- [x] Returns 404 if lessonId not found in tenant
- [x] Returns empty list if no qualified available teachers exist

## Technical Notes
Read-only query. Workload gap = workloadCap - count(assigned lessons this cycle).

## Dev Agent Record

### Implementation Plan
- Filtering reuses `CoverEligibilityService.availabilityAt`, the same snapshot COVER-01 validates against, so a teacher can never be suggested and then rejected on assignment.
- Availability is resolved with three queries for the whole candidate list rather than per candidate.
- Current workload counts lessons the teacher already *teaches* plus lessons they already *cover* — a cover assignment is real work and must consume capacity, otherwise repeated cover would look free.
- Ordering is workload gap descending, then display name so equal-capacity teachers come back in a stable order rather than an arbitrary one.

- (none)

### Completion Notes
- **"This cycle" is interpreted as "within the lesson's own timetable".** The technical note says workload gap = cap − assigned lessons *this cycle*, but no cycle boundary exists on `lessons` — SCHED-01/02 have not been built, and `lessons` carries only a `timetable_id` and a date. The timetable is the closest well-defined scope and is the one the lesson itself belongs to. Revisit when Epic 6 defines cycles properly.
- `workloadCap` is nullable, so an uncapped teacher gets `workloadCap: null` and `workloadGap: null` rather than a fabricated number, and sorts **first** — no ceiling means the most spare capacity. Covered by `get_uncappedTeacherSortsFirstWithNullGap`.
- The lesson's own teacher is excluded from the candidate list; they are who is being replaced, and COVER-01 rejects them as their own cover.
- `./mvnw -o test -Dtest='CoverCandidateEndpointTest'` → 14 passed.
