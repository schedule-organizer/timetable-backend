# Story AUTH-11 — MODERATOR Role Alignment & Reserved Roles
**Epic:** Epic 2 — Authentication & User Management | **Points:** 3 SP | **Status:** Not Started

## Description
Align the codebase with the PRD role model: rename **`MOD` → `MODERATOR`** everywhere (database, validation, JWT claims, `@PreAuthorize`), and add **reserved** role values **`STUDENT`** and **`PARENT`** (no MVP permissions) so future migrations do not require a breaking enum change.

**Traceability:** PRD §RBAC Matrix, §Implementation Notes, FR9, FR13.

## Acceptance Criteria
- [ ] Flyway migration updates existing `users.role` values from `MOD` to `MODERATOR` (additive migration; do not edit past migration files)
- [ ] All Java constants, validation sets, and tests use `MODERATOR` (not `MOD`); Spring Security expressions use `hasRole('MODERATOR')` / `hasAnyRole('ADMIN','MODERATOR',…)` as appropriate
- [ ] JWT / `JwtAuthenticationFilter` still builds `ROLE_` + role string — resulting authority is `ROLE_MODERATOR`
- [ ] `ChangeRoleRequest` and `UserService.changeRole` accept `ADMIN`, `MODERATOR`, `TEACHER`, and reject unknown strings with 400; reserved roles `STUDENT`, `PARENT` are **not** assignable via this endpoint in MVP (400 if requested) unless product explicitly defers — default: **not assignable**
- [ ] OpenAPI / controller docs list the canonical role names
- [ ] Unit and integration tests updated; no remaining references to `MOD` as a role literal in production code (comments may note historical name)

## Technical Notes
- Today: `UserService.VALID_ROLES` includes `MOD`; controllers use `hasAnyRole('ADMIN', 'MOD')` in places that will change in **CONFIG-10** (institution config) vs **MODERATOR** scheduling APIs (later epics)
- After this story, global find: `MOD` in security context should refer only to non-role strings (e.g. “mod” in paths) — verify with grep
- Epic 2 stories AUTH-01–AUTH-10 marked Done remain valid historically; **AUTH-09** completion notes mentioned `MOD` — update that story’s change log only if you maintain forward consistency (optional)
