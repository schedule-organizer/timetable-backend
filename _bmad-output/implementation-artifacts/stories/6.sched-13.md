# Story SCHED-13 — Schedule Checkpoints (Save & Restore)
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 5 SP | **Status:** Not Started

## Description
Implement **FR26–FR27**: MODERATOR (and ADMIN) can save a **named checkpoint** of the current timetable state and **restore** the timetable to any prior checkpoint. Supports the PRD innovation around checkpoint/rollback as a scheduling primitive.

**Traceability:** FR26, FR27, FR29 (version status — align with existing `DRAFT`/`PUBLISHED` model); Domain §Checkpoint safety.

## Acceptance Criteria
- [ ] New persistence: e.g. `timetable_checkpoints` table — `id`, `tenant_id`, `timetable_id`, `name`, `created_at`, `created_by_user_id`, snapshot payload (JSONB or normalized copy of lesson rows — **design choice documented**)
- [ ] `POST /api/v1/timetables/{timetableId}/checkpoints` — body: `{ "name": "..." }`; creates checkpoint of current lesson assignments; 403 if not ADMIN/MODERATOR; 404 wrong tenant
- [ ] `GET /api/v1/timetables/{timetableId}/checkpoints` — paginated list of checkpoints (newest first); metadata only or include size — document
- [ ] `POST /api/v1/timetables/{timetableId}/checkpoints/{checkpointId}/restore` — transactional restore: replaces current draft lessons from snapshot; idempotent behavior documented; 409 if timetable is **PUBLISHED** (restore only allowed for DRAFT — or product allows with explicit flag — **default: DRAFT only**)
- [ ] Retention: enforce **max N checkpoints per timetable** (config property, default e.g. 10) — deleting oldest or rejecting with 400 — match PRD “last 10 checkpoints” guidance
- [ ] All operations audited or logged at service level (optional AOP) — defer to EXPORT/audit epic if table not ready
- [ ] Integration tests: create lessons → checkpoint → mutate → restore → assert equality with checkpoint state

## Technical Notes
- Action endpoints use **POST** with verb segment per PRD API conventions (`/checkpoints`, `/restore`)
- **FR25** manual edits may land before this story — restore must interact correctly with `PATCH` lesson APIs
- WebSocket: optional `CHECKPOINT_CREATED` / `TIMETABLE_RESTORED` on `/topic/timetable/{id}` — nice-to-have; mark optional in tasks
