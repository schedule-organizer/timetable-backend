# Story SCHED-07 — Publish Timetable
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 3 SP | **Status:** done

## Description
`POST /api/v1/timetables/{id}/publish` — validate zero hard violations, set status PUBLISHED, record `published_at`; `@Scheduled` job for future-dated publish

## Acceptance Criteria
- [x] Validates timetable has zero hard constraint violations before publishing
- [x] Returns 400 with violation details if hard violations exist
- [x] Sets status to PUBLISHED, records `published_at` timestamp
- [x] Triggers `TIMETABLE_PUBLISHED` WebSocket event (NOTIF-02)
- [x] Supports `publishAt` parameter for future-dated publishing (stored, executed by `@Scheduled` job)
- [x] Only one PUBLISHED timetable allowed per term (existing published timetable auto-archived)

## Technical Notes
`@Scheduled` job checks for pending future-dated publishes every minute.

## Dev Agent Record

### Implementation Plan
- `POST /api/v1/timetables/{id}/publish`, with an optional `publishAt`. A future instant leaves the timetable DRAFT and stores the time; `TimetablePublishJob` sweeps every minute (cron overridable via `app.timetables.publish-sweep-cron`). A past or absent instant publishes immediately.
- **"Zero hard violations" is evaluated with `ConflictDetectionService`** — the same rules the grid's `hasConflict` flag uses. What a moderator sees on screen is exactly what blocks them, and the 400 names the count and the first few offending lesson ids so they need no second request.
- `applyPublication` is shared by the immediate path and the sweep, so a scheduled publish archives the term's previous timetable and emits the event identically.
- `V029` adds `published_at` and `publish_at`; the sweep is indexed on `(status, publish_at)`.

### Completion Notes
- The AC attributes `TIMETABLE_PUBLISHED` to NOTIF-02, which does not exist (Epic 8 is backlog). It is published here on the tenant topic through COVER-07's publisher — the same arrangement SCHED-06 uses.
- The sweep is idempotent: publishing clears `publish_at`, so a second pass finds nothing. Verified in `scheduledSweep_publishesTimetablesWhoseTimeHasCome`.
- Like COVER-06's expiry job, the sweep is deliberately cross-tenant — no `TenantContext` on the scheduler thread means the Hibernate filter stays off and it sees every tenant's rows.
- `./mvnw -o test -Dtest='TimetablePublishEndpointTest'` → 11 passed.
