# Story SCHED-14 — Targeted Partial Regeneration
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 5 SP | **Status:** Not Started

## Description
Implement **FR24**: MODERATOR can trigger a **re-generation scoped to a subset of resources** (e.g. specific teachers, classes, or rooms) such that **unrelated** lesson slots are not silently changed. Aligns with PRD domain rule: partial regeneration scope is always explicit.

**Traceability:** FR24; Domain §Partial regeneration scope.

## Acceptance Criteria
- [ ] API extends engine run contract (new endpoint or optional body on existing `POST /api/v1/engine/run` — pick one): accepts **timetable id**, existing solver parameters, plus **`scope`** describing included entity IDs (e.g. `teacherIds`, `classIds`, `roomIds` — at least one dimension supported in MVP)
- [ ] Solver integration: only lessons **within scope** are movable; pins and out-of-scope lessons remain fixed (document interaction with **SCHED-09** pinning)
- [ ] Response includes **diff summary** or job metadata referencing which slots were eligible vs frozen — “no silent change” is testable
- [ ] When scope is empty or invalid → **400** with clear message
- [ ] **403** for non ADMIN/MODERATOR; tenant isolation unchanged
- [ ] Integration or heavy unit test: small fixture proves out-of-scope lesson unchanged after run
