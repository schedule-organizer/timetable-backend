# Story AUTH-03 — Token Refresh
**Epic:** Epic 2 — Authentication & User Management | **Points:** 2 SP | **Status:** Done

## Description
`POST /api/v1/auth/refresh` — validates refresh cookie, returns new access token

## Acceptance Criteria
- [x] Reads refresh token from HttpOnly cookie
- [x] Returns new JWT access token if refresh token is valid and not expired
- [x] Returns 401 if refresh token is missing, invalid, or expired
- [x] Does not rotate refresh token (rotation is post-MVP)
- [x] Returns 401 if associated user account is INACTIVE

## Technical Notes
Refresh token lookup by token hash in DB. Validate expiry in DB, not just JWT claim.

## Tasks / Subtasks

- [x] T1: Add `refresh()` to AuthService + TokenRefreshResult record
  - [x] T1a: Look up RefreshToken by value → 401 if absent
  - [x] T1b: Check `expiresAt.isAfter(now)` → 401 if expired
  - [x] T1c: Load User by `refreshToken.getUserId()` → 401 if absent
  - [x] T1d: Check user status == ACTIVE → 401 if not
  - [x] T1e: Generate new JWT access token
  - [x] T1f: Return `TokenRefreshResult(accessToken, accessTokenExpiryMs)`
- [x] T2: Add `POST /api/v1/auth/refresh` to AuthController — reads cookie via `@CookieValue(required=false)`, 401 if null
- [x] T3: Unit tests — 4 cases: success, unknown token, expired token, inactive user
- [x] T4: Integration tests — RefreshEndpointTest: success after login, missing cookie, invalid token

## Dev Agent Record

### Implementation Plan
- `@Transactional(readOnly=true)` — refresh is read-only, no token rotation (post-MVP)
- All failure paths return the same 401 message to avoid oracle attacks
- Cookie extracted via `@CookieValue(required=false)`; null cookie throws `UnauthorizedException` before hitting the service

### Debug Log
- `Set-Cookie` header value from `ResponseCookie` needs `split("=", 2)[1]` (limit=2) to correctly extract UUID token values that could theoretically contain `=` padding characters.
