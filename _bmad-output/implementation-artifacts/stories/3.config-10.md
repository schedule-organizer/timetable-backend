# Story CONFIG-10 — Institution Configuration RBAC (ADMIN Only)
**Epic:** Epic 3 — Institution Configuration | **Points:** 2 SP | **Status:** done

## Description
Restrict **institution configuration** APIs to **ADMIN** only per the PRD RBAC matrix. MODERATOR must **not** create or mutate academic years, terms, bell schedules, or tenant settings.

**Traceability:** PRD §RBAC Matrix row “Institution configuration”; FR2–FR7 (ADMIN actions).

## Acceptance Criteria
- [x] All **write** operations (`POST`, `PUT`, `PATCH`, `DELETE`) on Epic 3 resources (`/api/v1/academic-years`, `/api/v1/terms`, `/api/v1/bell-schedules`, `/api/v1/settings`, and related) require `hasRole('ADMIN')` (after **AUTH-11** rename — use `MODERATOR` nowhere for these controllers)
- [x] **Read** operations: either **ADMIN-only** for consistency with “configuration” or **authenticated read** for non-admin UI needs — **default per PRD:** only ADMIN may access institution configuration endpoints unless product adds a separate read-only DTO for moderators; pick one and document in controller javadoc
- [x] `GET /api/v1/settings/public` remains **permitted without authentication** (unchanged)
- [x] MODERATOR users receive **403** on any institution-configuration endpoint they are not allowed to use
- [x] Integration tests: ADMIN succeeds; MODERATOR and TEACHER fail on writes; matrix covered for at least one controller per resource type

## Technical Notes
- **Depends on AUTH-11** so `@PreAuthorize` uses `MODERATOR` for future scheduling epics, not `MOD`
- Current code (e.g. `AcademicYearController`, `TermController`) uses `hasAnyRole('ADMIN', 'MOD')` — this story **removes** moderator/mod from config surfaces
- Update existing story files (e.g. CONFIG-01 AC) only if you maintain living requirements there — optional
