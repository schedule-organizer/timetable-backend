# Story HOL-03 — Manual Holiday Date CRUD
**Epic:** Epic 4 — Holiday & Vacation Calendar | **Points:** 2 SP | **Status:** done

## Description
Manual holiday date CRUD — add, edit, delete individual dates within a calendar

## Acceptance Criteria
- [x] `POST /api/v1/holidays/{calendarId}/dates` — add a single holiday date (date, name, type)
- [x] `PUT /api/v1/holidays/{calendarId}/dates/{dateId}` — edit name or type
- [x] `DELETE /api/v1/holidays/{calendarId}/dates/{dateId}` — remove a date
- [x] Returns 404 if calendarId or dateId not found in tenant
- [x] Duplicate dates within same calendar rejected (400)
- [x] Admin/Mod only

## Technical Notes
Manual dates coexist with imported dates; type distinguishes source.

## Dev Notes

### Architecture
- Controller → `com.schediflow.api.v1.HolidayDateController`
- Service → `com.schediflow.service.HolidayDateService`
- Repository → existing `com.schediflow.repository.HolidayDateRepository` (add methods)
- DTOs → `com.schediflow.dto.request/response`

### Key Rules
- `tenant_id` always from `TenantContext.getTenantId()` — never from client
- Calendar existence validated against tenant before date operations
- Duplicate date in same calendar → `BadRequestException` (400)
- calendarId not found → `ResourceNotFoundException` (404)
- dateId not in calendar/tenant → `ResourceNotFoundException` (404)
- `@PreAuthorize("hasAnyRole('ADMIN', 'MOD')")` on all write endpoints
- Existing UNIQUE index on (holiday_calendar_id, date) in V009 catches DB-level duplicates

### URL Path Note
Existing `HolidayImportController` is at `/api/v1/holidays/import` (fixed path).
New `HolidayDateController` is at `/api/v1/holidays/{calendarId}/dates` — no conflict since Spring
MVC prefers fixed path segments over path variables.
