# Story HOL-07 — Holiday Conflict Detection
**Epic:** Epic 4 — Holiday & Vacation Calendar | **Points:** 3 SP | **Status:** done

## Description
Conflict detection: `ConflictDetectionService` warns when a published lesson falls on a newly added holiday date

## Acceptance Criteria
- [x] When a new holiday date is added (manual or imported), checks all PUBLISHED timetables for affected term
- [x] Returns list of affected lessons (lessonId, subject, teacher, class, conflicting date)
- [x] Does not auto-cancel lessons — returns warnings only
- [x] Triggered on both HOL-02 (import) and HOL-03 (manual add) operations
- [x] Returns empty list if no conflicts found

## Technical Notes
Integrates with `ConflictDetectionService` from SCHED-11.

## Tasks / Subtasks
- [x] Add `ConflictDetectionService` with `findPublishedLessonHolidayConflicts(tenantId, academicYearId, holidayDate)`
- [x] Persist minimal `lessons` table (V015) + `Lesson` entity + `LessonRepository` JPQL for published lessons on a date within term scope
- [x] Extend `HolidayDateResponse` / `HolidayImportResponse` with `lessonConflicts`; wire `HolidayDateService.addDate` and `HolidayImportService.importPublicHolidays`
- [x] Unit tests (`ConflictDetectionServiceTest`, update holiday service tests) and endpoint JSON assertions
- [x] Run full test suite (local Java 21)

### Review Findings

- [x] [Review][Defer] Per-date conflict queries on holiday import — `HolidayImportService` loops `findPublishedLessonHolidayConflicts` once per distinct newly inserted date; acceptable for typical public-holiday feeds; batch into one query if import volume grows. [`HolidayImportService.java` ~L97] — deferred, optimisation

## Dev Agent Record

### Implementation Plan
- Introduced `ConflictDetectionService` (holiday scope now; SCHED-11 will add move/swap double-booking checks on same service type).
- Terms for the holiday calendar’s academic year that contain the holiday date → collect term IDs; query `lessons` joined to `timetables` with `status = PUBLISHED` and related subject/class/user for names.
- Teacher display: `COALESCE(display_name, email)` in JPQL.
- `HolidayDateResponse.lessonConflicts` empty on list-by-year; populated on manual add. `HolidayImportResponse.lessonConflicts` aggregates warnings for each newly inserted holiday date (import).
- No DB mutations beyond normal holiday add/import — warnings only.

### Debug Log
- CI/local: `mvn test` requires Java 21 per `pom.xml`; sandbox had JDK 17 only — compile step not executed in agent environment.

### Completion Notes
- `/api/v1/holidays/{calendarId}/dates` POST and `/api/v1/holidays/import` POST now return `lessonConflicts` with affected published lessons when present.
- V015 `lessons` enables future SCHED-02 grid API to reuse the same table.
