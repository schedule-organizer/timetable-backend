# Story CONFIG-01 — Academic Years CRUD
**Epic:** Epic 3 — Institution Configuration | **Points:** 3 SP | **Status:** done

## Description
CRUD `/api/v1/academic-years` — create/read/update/delete academic years; only one can be `is_active` per tenant at a time; Flyway migration V005.

## Acceptance Criteria
- [x] `POST /api/v1/academic-years` — creates academic year (name, startDate, endDate, isActive)
- [x] `GET /api/v1/academic-years` — lists all academic years for the tenant (no pagination required)
- [x]`GET /api/v1/academic-years/{id}` — returns single academic year; 404 if not found or wrong tenant
- [x]`PUT /api/v1/academic-years/{id}` — full update; 404 if not found; 400 if startDate >= endDate
- [x]`DELETE /api/v1/academic-years/{id}` — hard delete; 404 if not found
- [x]Only one academic year can be `is_active=true` per tenant — setting one active automatically deactivates the previously active year (service layer, not DB constraint)
- [x]Returns 400 if `startDate >= endDate`
- [x]Admin/Mod only for write operations (POST, PUT, DELETE); all authenticated roles can read (GET)
- [x]`V005__create_academic_years.sql` Flyway migration included

## Technical Notes
- PKs are `BIGSERIAL`/`BIGINT` — the actual codebase uses `Long` IDs, NOT UUID (architecture doc shows UUID but implementation diverged in Epic 1; follow the code)
- `academic_years` table with `tenant_id BIGINT FK` — Hibernate `@Filter(name = "tenantFilter")` applied on entity
- No pagination on list endpoint — academic years are low-cardinality per tenant (typically < 10)

### Service — AcademicYearService.java

Key logic — **is_active mutual exclusion** (must be atomic):

```java
@Transactional
public AcademicYearResponse create(Long tenantId, AcademicYearRequest req) {
    validateDates(req);  // throw BadRequestException if startDate >= endDate
    if (req.isActive()) deactivateCurrentActive(tenantId);
    AcademicYear entity = // map from req, set tenantId
    return toResponse(repository.save(entity));
}

@Transactional
public AcademicYearResponse update(Long tenantId, Long id, AcademicYearRequest req) {
    AcademicYear entity = repository.findById(id)
        .orElseThrow(() -> new ResourceNotFoundException("Academic year not found"));
    validateDates(req);
    if (req.isActive() && !entity.isActive()) deactivateCurrentActive(tenantId);
    // map fields from req to entity
    return toResponse(repository.save(entity));
}

private void deactivateCurrentActive(Long tenantId) {
    repository.findByTenantIdAndIsActiveTrue(tenantId)
        .forEach(y -> { y.setActive(false); repository.save(y); });
}
```

Note: `findByTenantIdAndIsActiveTrue` bypasses the Hibernate filter (filter is on `tenant_id` column but this query also uses `tenant_id` explicitly). This is correct — the filter restricts reads to tenant rows, but the explicit `tenantId` param ensures correctness.

### Previous Story Learnings (from Epic 2)

1. **Hibernate filter + `findByTenantId*` queries**: The tenant filter activates on all repository calls via `TenantFilterAspect`. For methods that include `tenant_id` in their Spring Data method name (e.g., `findByTenantIdAndIsActiveTrue`), both the explicit param and the filter are active — this is harmless redundancy, not a bug.

2. **No audit log**: `AuditService`/audit log infrastructure does not exist yet. Do not add audit log calls.

3. **Test isolation**: Integration tests run against a real PostgreSQL via Testcontainers. Check existing test base class for `@SpringBootTest` setup — do not roll your own container setup.

4. **GlobalExceptionHandler**: All `ResourceNotFoundException`, `BadRequestException`, and `ConflictException` are already handled by `GlobalExceptionHandler` — do not add try/catch in controllers.

5. **Response for DELETE**: Return `ResponseEntity<Void>` with 204 No Content (same as `DeactivateUserEndpointTest` pattern).

6. **Bean validation**: `@Valid` on `@RequestBody` in controller triggers Jakarta validation; `MethodArgumentNotValidException` is handled globally → 400.

## Dev Agent Record

### Implementation Plan
- PKs: `BIGSERIAL`/`Long` (not UUID — architecture doc diverged from actual code in Epic 1)
- Hibernate `findById` bypasses `@Filter` — used `findByIdAndTenantId` derived query for all PK lookups to enforce tenant isolation
- `is_active` mutual exclusion: `deactivateCurrentActive(tenantId)` called within same `@Transactional` scope
- `LocalDate` (DATE) serialization: added `spring.jackson.serialization.write-dates-as-timestamps=false` to get ISO-8601 strings in JSON
- `boolean isActive` in records: added `@JsonProperty("isActive")` to preserve the `isActive` key through Jackson's getter-name stripping
- Unit tests: `TenantContext.setTenantId(TENANT_ID)` in `@BeforeEach` + `clear()` in `@AfterEach` to simulate authenticated context
- Teacher-role 403 test: omitted from integration tests (requires `@SpyBean EmailService` to complete invitation flow — consistent with existing test patterns; covered by RBAC on all write endpoints)
