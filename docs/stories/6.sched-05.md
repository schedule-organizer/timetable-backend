# Story SCHED-05 — Cancel Solver Job
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 2 SP | **Status:** done

## Description
`POST /api/v1/engine/jobs/{id}/cancel` — cancel a running solver job; update status to CANCELLED

## Acceptance Criteria
- [x] Calls `SolverManager.terminateEarly(jobId)`
- [x] Updates job status to CANCELLED
- [x] Returns 404 if job not found in tenant
- [x] Returns 400 if job is already in terminal state (COMPLETED, FAILED, CANCELLED)
- [x] Best solution found before cancellation is retained in DB
- [x] Admin/Mod only

## Technical Notes
Timefold `SolverManager.terminateEarly` is non-blocking. Status updated via solver listener.

## Dev Agent Record

### Implementation Plan
- `POST /api/v1/engine/jobs/{id}/cancel` calls `SolverManager.terminateEarly`, which is non-blocking, then records CANCELLED with a completion timestamp.
- Cancelling an already-terminal job is a 400.
- **Retaining the best solution** falls out of the design: `terminateEarly` still triggers the final-best callback, and `recordCompletion` writes those lesson placements while deliberately *not* overwriting a terminal status. So a cancelled job keeps CANCELLED and still keeps its work.
