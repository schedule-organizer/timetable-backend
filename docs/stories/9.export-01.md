# Story EXPORT-01 — PDF Timetable Export
**Epic:** Epic 9 — Export & Reporting | **Points:** 5 SP | **Status:** done

## Description
`GET /api/v1/timetables/{id}/export/pdf` — generate printable PDF timetable grid; class, teacher, and room views; library TBD (TD-05: Flying Saucer vs headless Chrome)

## Acceptance Criteria
- [x] Generates PDF timetable grid for: class view, teacher view, room view (query param `view=CLASS|TEACHER|ROOM`)
- [x] PDF includes: school name, timetable name, term dates, grid of periods × days with lesson details
- [x] Returns PDF as `Content-Type: application/pdf` with `Content-Disposition: attachment`
- [x] Returns 404 if timetable not found in tenant
- [x] PDF generation completes in < 10 seconds for typical school (< 500 lessons)
- [x] Admin/Mod only

## Technical Notes
TD-05 decision: Flying Saucer (`xhtmlrenderer`) for MVP. If pixel-perfect required, switch to headless Chrome (Playwright). HTML template → PDF pipeline.

## Dev Agent Record

### Implementation Plan
- **TD-05 resolved in favour of Flying Saucer.** Thymeleaf renders an XHTML grid, `ITextRenderer` turns it into PDF, all in-process with no browser to install or keep alive. That is what makes the "< 10 seconds" target comfortable; headless Chrome would only earn its complexity if pixel-perfect fidelity were required, and no AC asks for it.
- The grid is always periods × days. The `view` parameter decides what each section is grouped under and what each cell shows — a CLASS view names subject/teacher/room, a TEACHER view names subject/class/room, a ROOM view names subject/class/teacher. Each cell states what its heading does not.
- Header carries school name, timetable name and the term with its dates, as the AC requires.

### Completion Notes
- Lessons with no room appear under "(no room)" in the ROOM view rather than being dropped — an unroomed lesson is exactly what someone printing a room view wants to notice.
- An empty timetable still produces a valid one-page PDF saying so, rather than an error or a zero-byte file.
- `view` is case-insensitive and defaults to CLASS; anything unrecognised is a 400.
- Tests assert the `%PDF-` magic bytes and a plausible document size across all three views.
