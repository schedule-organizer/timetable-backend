# Story AUTH-12 — Dual Role (TEACHER + MODERATOR)
**Epic:** Epic 2 — Authentication & User Management | **Points:** 5 SP | **Status:** Not Started

## Description
Implement **FR10**: an ADMIN can grant a TEACH user the **additional** MODERATOR capability (dual role). The PRD states that effective access may be represented as a **single role in the JWT** with optional **role elevation** via a dedicated endpoint.

**Traceability:** PRD §RBAC Matrix (last row), FR9–FR10, §API Conventions (dual-role users).

## Acceptance Criteria
- [ ] Data model supports multiple roles per user within a tenant (e.g. `user_roles` join table with `(user_id, role)` uniqueness, or equivalent normalized design — **not** a comma-separated string column)
- [ ] Existing single-role users migrate cleanly: each current `users.role` becomes one row in the new structure (or keep `users.role` as “primary” and add junction — document the chosen model in `UserService` javadoc)
- [ ] ADMIN-only API to set roles for a user: either extend `PUT /api/v1/users/{id}/role` to accept a structure that can express “TEACHER + MODERATOR” **or** add `PUT /api/v1/users/{id}/roles` (replaces or complements single-role endpoint — avoid ambiguous partial updates)
- [ ] Business rules: ADMIN cannot remove own ADMIN; at least one ADMIN per tenant remains enforceable or explicitly deferred with a TODO and test for the happy path
- [ ] JWT continues to satisfy FR13: claims include `sub`, `tenantId`, `email`, and **either** a `role` string for “effective” mode **or** a `roles` array — document choice; server-side `@PreAuthorize` must not trust client-only role headers
- [ ] Optional: `POST /api/v1/auth/elevate` (or similar) swaps effective JWT role between TEACHER and MODERATOR when the user has both (returns new access token); if omitted, document “effective role = MODERATOR when dual” for MVP
- [ ] Integration tests: dual-role user can call an endpoint requiring `MODERATOR` when elevated or when effective role is MODERATOR; TEACHER-only endpoints still work when effective is TEACHER

## Technical Notes
- Depends on **AUTH-11** (canonical `MODERATOR` string) — implement after or in same sprint with AUTH-11 merged first
- Spring Security method security may need a custom `PermissionEvaluator` or **custom `GrantedAuthority`** list from JWT if multiple roles exist
- Consider idempotency and invite flow: default invite remains TEACHER; ADMIN promotes later
