# Story AUTH-01 — Institution Self-Registration
**Epic:** Epic 2 — Authentication & User Management | **Points:** 3 SP | **Status:** Done

## Description
`POST /api/v1/auth/register` — institution self-registration: creates `Tenant` + first `Admin` user, returns JWT

## Acceptance Criteria
- [x] Endpoint accepts: institution name, admin email, admin password
- [x] Creates `Tenant` record with unique slug derived from institution name
- [x] Creates first `User` with role `ADMIN` linked to the new tenant
- [x] Returns JWT access token + sets HttpOnly refresh cookie
- [x] Returns 409 if email already registered
- [x] Password validated: min 8 chars, at least one number
- [x] Triggers `CONFIG-09` seed service to apply institution defaults

## Technical Notes
Runs in a single transaction. Slug must be URL-safe and unique.

## Dev Agent Record

### Implementation Plan
- Refresh token stored as UUID in DB (enables server-side invalidation for AUTH-04)
- Global email uniqueness (matches V001 migration index)
- Slug: lowercase, collapse non-alphanumeric to `-`, suffix counter for duplicates
- HttpOnly cookie path scoped to `/api/v1/auth/refresh`

### Debug Log
- Fixed 3 Mockito `PotentialStubbingProblem` errors in unit tests: (1) `anyString()` does not match `null` fields on mock return objects — fixed by setting email/role on returned User mocks and using specific argument matchers; (2) slug test expected `st-marys-college` but apostrophe splits the word, corrected to `st-mary-s-college`.
- QA review fix: `expiresIn` was returning refresh token TTL (604800s) instead of access token TTL (900s). Root cause: `AuthController` read `result.refreshTokenExpiryMs()` instead of `result.accessTokenExpiryMs()`. Fixed by adding `getAccessTokenExpiryMs()` to `JwtTokenProvider`, carrying it through `RegistrationResult`, and correcting the controller.
- QA review fix: slug truncation at 60 chars allowed counter suffixes to push candidates past 63 chars. Fixed by truncating base to 55 chars (accommodates up to "-9999" safely).
