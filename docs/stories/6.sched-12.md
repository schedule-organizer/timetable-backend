# Story SCHED-12 — Lesson Updated WebSocket Broadcast
**Epic:** Epic 6 — Timetable & Scheduling Engine | **Points:** 2 SP | **Status:** done

## Description
WebSocket: broadcast `LESSON_UPDATED` to `/topic/timetable/{timetableId}` on every lesson mutation (move, pin, swap, solver result)

## Acceptance Criteria
- [x] `LESSON_UPDATED` event published to `/topic/timetable/{timetableId}` on: move (SCHED-08), pin (SCHED-09), swap (SCHED-10), solver best solution (SCHED-06)
- [x] Event payload: `{ lessonId, timetableId, periodId, roomId, teacherId, isPinned, hasConflict, timestamp }`
- [x] Events scoped to tenant (no cross-tenant leakage via topic auth)
- [x] WebSocket subscription requires valid JWT

## Technical Notes
Depends on NOTIF-01 (`WebSocketEventPublisher`). Topic-level security via `ChannelInterceptor`.

## Dev Agent Record

### Implementation Plan
- `WebSocketDestinations` gains `timetableTopic(id)` and its parser, so the publisher and the SUBSCRIBE authorization use one definition of the destination.
- **Topic-level security needed a database lookup.** `/topic/timetable/{id}` carries no tenant in its path, so `StompAuthChannelInterceptor` now resolves ownership from the row: subscribing to a timetable outside your institution is rejected at SUBSCRIBE. Without this, the simple broker would happily deliver another tenant's grid updates.
- `WebSocketEventPublisher.publishToTopic` takes a destination already built by `WebSocketDestinations`, keeping hand-built strings out of callers.

### Completion Notes
- Published on move (SCHED-08), pin (SCHED-09) and swap (SCHED-10). The solver path (SCHED-06) will publish the same event when it writes lessons.
- `teacherId` in the payload is a `teachers.id`, resolved from the lesson's `teacher_user_id`, matching how the rest of the API identifies teachers.
- Tests: `StompAuthChannelInterceptorTest` grew to 15 (2 new for timetable topics).
