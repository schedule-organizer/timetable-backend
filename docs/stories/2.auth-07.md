# Story AUTH-07 — Own Profile Read/Update
**Epic:** Epic 2 — Authentication & User Management | **Points:** 3 SP | **Status:** Done

## Description
`GET/PUT /api/v1/users/me` — read and update authenticated user's own profile

## Acceptance Criteria
- [x] `GET /api/v1/users/me` returns current user's profile (id, email, displayName, role, status)
- [x] `PUT /api/v1/users/me` allows updating: displayName, password (requires current password confirmation)
- [x] Email is not changeable via this endpoint
- [x] Returns 401 if unauthenticated
- [x] Password update: validates current password before accepting new password

## Technical Notes
- Password field never returned in response — `UserResponse` DTO
- `currentPassword` required when `newPassword` is provided; wrong current password → 400
- Both fields optional in request body (can update displayName only, password only, or both)
- Uses `@AuthenticationPrincipal JwtPrincipal` to identify caller

## Dev Agent Record

### Implementation Plan
- `UserResponse(Long id, String email, String displayName, String role, String status)` — plain record, no password
- `UpdateProfileRequest(String displayName, String currentPassword, String newPassword)` — all optional; `@Size` on newPassword
- `getMe`: `userRepository.findById(userId)` → `toResponse(user)`
- `updateMe`: load user; if `newPassword` non-null → verify `currentPassword` via BCrypt (400 if wrong) → re-hash; update `displayName` if provided; save
