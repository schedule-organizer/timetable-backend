# Story CONFIG-03 — Bell Schedules & Periods CRUD
**Epic:** Epic 3 — Institution Configuration | **Points:** 4 SP | **Status:** done

## Description
CRUD `/api/v1/bell-schedules` + nested periods — bell schedule with named periods, times, break/lunch flags; one default per tenant; Flyway migration

## Acceptance Criteria
- [x] CRUD for bell schedules (name, isDefault) and nested periods (name, startTime, endTime, isBreak, isLunch, ordinal)
- [x] Only one bell schedule can be `isDefault=true` per tenant
- [x] Periods are created/updated/deleted via nested operations on the schedule endpoint
- [x] `V007__create_bell_schedules.sql` Flyway migration included
- [x] Periods validated: no overlapping times within same schedule
- [x] Returns 400 if deleting the only default schedule

## Technical Notes
`bell_schedules` and `schedule_periods` tables with tenant_id FK.

### Architecture Compliance

Follow established Epic 1–3 patterns exactly:

| Pattern | Implementation |
|---|---|
| PKs | `BIGSERIAL` in SQL / `Long id` in Java (NOT UUID) |
| Tenant isolation | `@Filter(name = "tenantFilter", condition = "tenant_id = :tenantId")` on `BellSchedule` entity; auto-activated by `TenantFilterAspect` |
| DTOs | Java `record` — never serialize JPA entities to responses |
| Controller security | `@PreAuthorize("hasAnyRole('ADMIN', 'MOD')")` on write methods |
| Tenant extraction | `@AuthenticationPrincipal JwtPrincipal principal` → `principal.tenantId()` |
| DI | Constructor injection only |
| Transactions | `@Transactional` on service write methods |
| Exceptions | `ResourceNotFoundException` (404), `BadRequestException` (400) |
| No Lombok | Manual getters/setters |

## Dev Agent Record

### Implementation Plan
- Next migration: V007 (V006 is `create_terms`)
- `boolean defaultSchedule` → column `is_default` (avoids Java reserved word `default`)
- Periods replaced wholesale on PUT (`@Modifying @Query` bulk delete + re-insert in same transaction)
- Overlap check: O(n²) pairwise — acceptable for small period lists (typically ≤ 10)
- `SchedulePeriod` has no Hibernate filter; tenant isolation guaranteed via parent bell schedule lookup

### Debug Log
- `put_updatesScheduleAndPeriods` failed (500): derived `deleteAllByBellScheduleId` loads entities into JPA cache then marks for deletion, but DELETE SQL wasn't flushed before INSERT → unique constraint violation on `(bell_schedule_id, ordinal)`. Fixed by replacing with `@Modifying @Query("DELETE FROM SchedulePeriod sp WHERE sp.bellScheduleId = :bellScheduleId")` which executes immediately as a bulk JPQL delete.
