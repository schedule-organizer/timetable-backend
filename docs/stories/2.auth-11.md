# Story AUTH-11 — MODERATOR Role Alignment & Reserved Roles
**Epic:** Epic 2 — Authentication & User Management | **Points:** 3 SP | **Status:** done

## Description
Align the codebase with the PRD role model: rename **`MOD` → `MODERATOR`** everywhere (database, validation, JWT claims, `@PreAuthorize`), and add **reserved** role values **`STUDENT`** and **`PARENT`** (no MVP permissions) so future migrations do not require a breaking enum change.

**Traceability:** PRD §RBAC Matrix, §Implementation Notes, FR9, FR13.

## Acceptance Criteria
- [x] Flyway migration updates existing `users.role` values from `MOD` to `MODERATOR` (additive migration; do not edit past migration files)
- [x] All Java constants, validation sets, and tests use `MODERATOR` (not `MOD`); Spring Security expressions use `hasRole('MODERATOR')` / `hasAnyRole('ADMIN','MODERATOR',…)` as appropriate
- [x] JWT / `JwtAuthenticationFilter` still builds `ROLE_` + role string — resulting authority is `ROLE_MODERATOR`
- [x] `ChangeRoleRequest` and `UserService.changeRole` accept `ADMIN`, `MODERATOR`, `TEACHER`, and reject unknown strings with 400; reserved roles `STUDENT`, `PARENT` are **not** assignable via this endpoint in MVP (400 if requested) unless product explicitly defers — default: **not assignable**
- [x] OpenAPI / controller docs list the canonical role names
- [x] Unit and integration tests updated; no remaining references to `MOD` as a role literal in production code (comments may note historical name)

## Dev Agent Record


### Implementation Plan
- Rewrote **quoted role literals only** (`'MOD'`, `"MOD"`) rather than a blind find-replace, so `MODERATOR` could never be partially matched. Verified afterwards that no `MODERATORERATOR` exists anywhere and that zero bare `MOD` role references remain in production or tests. 50 files rewritten — 26 production, 24 test — plus javadoc in 23 more, since the AC requires docs to carry the canonical names too.
- `V035` corrects the data forward without touching past migrations, as the story requires. V001 declared `users.role` as a plain `VARCHAR` with no CHECK, so no constraint had to be dropped or recreated.
- New `Role` constants class holds the canonical names. String constants rather than an enum because `users.role` is a plain column and `@PreAuthorize` expressions need compile-time constants.
- `STUDENT` and `PARENT` are declared but **not assignable**, per the AC's stated default. `changeRole` rejects them with a message saying *why* — they carry no permissions, so granting one would silently strip a user of all access, which is a worse outcome than a 400.

### Completion Notes
- **This invalidates every issued JWT.** The `role` claim is embedded in the token, so one minted before deploy still says `MOD`, matches no authority, and yields 403s until the user re-authenticates. Access tokens live 15 minutes, so the window is short. Called out in the V035 header, where whoever deploys will see it.
- `2.auth-11` and `2.auth-12` are now present in `sprint-status.yaml` for the first time. They had existed as story files since the 2026-03-29 readiness review and were invisible to sprint tracking — the last of the four untracked stories flagged in the initial project analysis.
- AUTH-12 (dual TEACHER + MODERATOR role, FR10) remains `ready-for-dev`. It is a genuine feature, not part of this rename.
