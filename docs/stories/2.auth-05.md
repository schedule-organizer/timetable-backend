# Story AUTH-05 — Teacher Invitation
**Epic:** Epic 2 — Authentication & User Management | **Points:** 5 SP | **Status:** Done

## Description
`POST /api/v1/users/invite` — create `PENDING_REGISTRATION` user, generate single-use 72h token, send invite email via `StubEmailService` (NOTIF-03 will replace with real SMTP)

## Acceptance Criteria
- [x] Admin/Mod creates user with status `PENDING_REGISTRATION`
- [x] Generates single-use invitation token (raw UUID in email link, SHA-256 hash stored in DB)
- [x] Token expires after 72 hours
- [x] Sends invitation email via `StubEmailService` (logs link; no SMTP dependency yet)
- [x] Returns 409 if email already exists as ACTIVE in tenant
- [x] Invitation can be re-sent: new token issued, old invalidated, if user is PENDING_REGISTRATION

## Technical Notes
- Token: raw UUID sent in link, SHA-256 hex digest stored in `invitation_tokens.token_hash`
- `EmailService` interface; `StubEmailService` logs the link — real SMTP deferred to NOTIF-03
- Re-send: delete existing `invitation_tokens` for user, create new token, send email again
- 409 only for ACTIVE users; re-send for PENDING_REGISTRATION
- `@PreAuthorize("hasAnyRole('ADMIN', 'MOD')")` on controller method
- `@Value("${app.frontend-url}")` injected into `UserService`
- Default role: TEACHER

## Dev Agent Record

### Implementation Plan
- V003 migration adds `invitation_tokens` table with FK to `users`
- Raw UUID → SHA-256 hex → stored in `token_hash VARCHAR(64) UNIQUE`
- `UserService` (new service) injected with `UserRepository`, `InvitationTokenRepository`, `EmailService`, `@Value("${app.frontend-url}")`
- `UserController` (new controller) at `/api/v1/users`, `POST /invite` requires `ROLE_ADMIN` or `ROLE_MOD`
- `StubEmailService` logs: `[EMAIL] Invite link for <email>: <frontendUrl>/complete-registration?token=<rawToken>`
- SecurityConfig needed no changes — `/api/v1/users/invite` falls through to `anyRequest().authenticated()` and `@PreAuthorize` handles role

### Debug Log
- `@PreAuthorize("hasAnyRole('ADMIN', 'MOD')")` works because `@EnableMethodSecurity` is already set in `SecurityConfig` and roles are stored as `ROLE_<role>` — Spring strips the prefix for `hasAnyRole`.
- The `invite_activeUser_returns409` integration test uses the admin's own email (ACTIVE in their tenant) to trigger the 409 path — clean without needing a separate "complete-registration" flow.
