## Dev Agent Record

### Implementation Plan
- **Extends the existing `POST /api/v1/engine/run`** with an optional `scope`, rather than adding a second endpoint. The AC allowed either; one endpoint keeps mode, timeout and scope in a single contract, and an absent scope is exactly today's full run.
- **Scope is enforced by pinning.** Out-of-scope lessons are marked pinned in the planning model, so Timefold cannot move them — the same mechanism SCHED-09 uses. That is what makes "unrelated slots are not silently changed" structural rather than advisory, and it composes cleanly: a lesson is frozen if it was pinned by hand *or* excluded by scope.
- A lesson is in scope if it matches **any** supplied dimension (`teacherIds`, `classIds`, `roomIds`), so a moderator can widen a run without enumerating every combination.
- V031 records `scope_description`, `eligible_lessons` and `frozen_lessons` on the job, so the "no silent change" claim is auditable after the run, not just at request time.

### Completion Notes
- An empty scope object is a 400 rather than being treated as "everything" — silently regenerating the whole timetable when someone meant to narrow it is the exact failure this story exists to prevent.
- A scope matching no lessons is accepted and freezes everything: it is a valid, if pointless, request, and reporting `eligibleLessons: 0` is clearer than an error.
- `scope_test` proves the AC's core claim directly: an out-of-scope lesson holds its exact period across a real solve.
- `./mvnw -o test -Dtest='PartialRegenerationEndpointTest'` → 8 passed.
