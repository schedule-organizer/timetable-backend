# Story CONFIG-05 — Public Settings Endpoint
**Epic:** Epic 3 — Institution Configuration | **Points:** 1 SP | **Status:** done

## Description
`GET /api/v1/settings/public` — unauthenticated endpoint returning locale/timezone for login page

## Acceptance Criteria
- [x] Unauthenticated endpoint (no JWT required)
- [x] Tenant identified by subdomain or `tenantSlug` query param
- [x] Returns only: locale, timezone, institutionName
- [x] Returns 404 if tenant slug not found or tenant is inactive
- [x] Response cached (e.g., 5 min TTL) to avoid DB hit on every login page load

## Technical Notes
Must be excluded from JWT filter and multi-tenancy filter. Tenant resolved by slug, not from JWT.

## Tasks / Subtasks

- [x] T1: Add `spring-boot-starter-cache` + Caffeine dependencies to `pom.xml`; create `CacheConfig` with a 5-minute TTL Caffeine cache named `publicSettings`.
- [x] T2: Create `PublicSettingsResponse` record DTO with `locale`, `timezone`, and `institutionName` fields.
- [x] T3: Add `getPublicSettings(String tenantSlug)` to `TenantSettingsService`: find tenant by slug, reject inactive, extract locale/timezone from settings blob, return `PublicSettingsResponse`. Annotate with `@Cacheable(value = "publicSettings", key = "#tenantSlug")`.
- [x] T4: Add `GET /api/v1/settings/public` to `SecurityConfig.permitAll()`. Add the endpoint handler to `SettingsController` accepting `tenantSlug` query param.
- [x] T5: Add service unit tests for `getPublicSettings` (valid slug, unknown slug, inactive tenant, empty settings).
- [x] T6: Create `PublicSettingsEndpointTest`: unauthenticated access returns 200, correct fields returned, missing param returns 400, unknown slug returns 404, inactive tenant returns 404.

## Dev Notes
- `TenantRepository.findBySlug(String)` already exists — use it directly.
- Tenant `status` field is stored as a String (e.g., `"ACTIVE"`). Return 404 for any non-`ACTIVE` tenant to avoid information leakage.
- `institutionName` comes from `tenant.getName()`, not the settings blob.
- Subdomain resolution is deferred — `tenantSlug` query param is the supported mechanism.
- The `TenantFilter` and `JwtAuthenticationFilter` already skip non-bearer requests gracefully; no changes needed to those filters.
- Use `@DirtiesContext(classMode = AFTER_EACH_TEST_METHOD)` is noted in the codebase as an anti-pattern per review findings — do NOT use it. Tests for the public endpoint are read-only so isolation via UUID institution names is sufficient.

### Implementation Plan
- Added `spring-boot-starter-cache` + `caffeine` to `pom.xml`. Created `CacheConfig` with `@EnableCaching` and a 5-min expiry Caffeine cache named `publicSettings`.
- New `PublicSettingsResponse` record at `com.schediflow.dto.response`.

- `SettingsController` adds the handler (no `@AuthenticationPrincipal` — fully public).
- `GlobalExceptionHandler` extended with `MissingServletRequestParameterException` → 400 handler (pre-existing gap exposed by new endpoint).
- Fixed pre-existing H2 JSONB double-encoding bug in `TenantSettingsService.parseSettings`: H2 in PostgreSQL mode returns JSONB values double-encoded via `getString()` (e.g. `{}` → `"{}"`). Added one-level unwrap for `TextNode` results.
- Fixed two pre-existing `TenantSettingsServiceTest` failures: removed unnecessary stub in `updateSettings_nonObjectPayload_rejected`; corrected `updateSettings_exceedsMaxDepth_rejected` to pre-seed nested settings so the depth guard actually triggers.

- H2 JSONB bug: H2 returns `"{}"` (double-quoted string) via `getString()` for JSONB columns in PostgreSQL mode. Fixed in `parseSettings` with a TextNode unwrap guard.
- Pre-existing rate-limiting failures remain in `TenantSettingsEndpointTest` (4), `LogoutEndpointTest` (1), `TermEndpointTest` (1) — all setUp 429 errors, not related to CONFIG-05.
