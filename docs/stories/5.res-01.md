## Description
CRUD `/api/v1/rooms` — room type, capacity, equipment tags, building/floor; Flyway migration

## Dev Agent Record

### Implementation Plan
- Room entity stored in `rooms` table with tenantId, name, type (VARCHAR), capacity, equipmentTags (TEXT comma-delimited), building, floor, isActive, createdAt
- equipmentTags serialized as comma-delimited TEXT via AttributeConverter
- Soft delete: DELETE endpoint sets isActive=false
- Name uniqueness enforced per-tenant via DB unique index + service-level check
- Read endpoints open to all authenticated roles; write endpoints restricted to ADMIN/MOD via @PreAuthorize

### Debug Log

### Completion Notes
All 8 tasks complete. 24 endpoint tests + 12 service tests pass. Partial index in Flyway migration replaced with plain indexes (H2 in MODE=PostgreSQL does not support WHERE clause in CREATE INDEX); name uniqueness enforced at service layer for active rooms only, which supports the soft-delete → name-reuse flow verified in `delete_softDelete_allowsReuseOfName`.
