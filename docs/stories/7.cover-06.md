# Story COVER-06 — Auto-Expire Temporary Schedules
**Epic:** Epic 7 — Cover, Delegation & Temporary Schedules | **Points:** 3 SP | **Status:** done

## Description
`@Scheduled` job: auto-expire temporary schedules at `end_date`; revert lessons to base timetable

## Acceptance Criteria
- [x] `@Scheduled` job runs daily (or at configurable interval)
- [x] Identifies temporary schedules where `end_date` < today
- [x] Sets status to EXPIRED
- [x] Clears temporary lesson overrides (base timetable lessons resume automatically)
- [x] Idempotent: safe to run multiple times on same day
- [x] Logs expiry actions for audit

## Technical Notes
Use `@Scheduled(cron = "0 0 1 * * *")` (1 AM daily). No notification required for expiry.

## Dev Agent Record

### Implementation Plan
- The cron defaults to the story's `0 0 1 * * *` but is overridable via `app.temporary-schedules.expiry-cron`, satisfying "or at configurable interval" without a code change.
- The sweep is deliberately **cross-tenant**. There is no `TenantContext` on the scheduler thread, so `TenantFilterAspect` leaves the Hibernate tenant filter disabled and the query sees every tenant's rows — which is what a system job needs. Verified by `sweepsEveryTenant`.
- Reverting to the base timetable is a *deletion*, not an undo: because COVER-05 stores overrides in their own table and never mutates `lessons`, removing the override rows is sufficient for the base schedule to apply again.
- Idempotence comes from the selection predicate — only `ACTIVE` overlays are picked up, and expiring one moves it out of that set. `isIdempotent` runs the sweep three times and asserts only the first does work.
- `end_date < today` is a strict comparison, so an overlay is still in force on its final day; `doesNotExpireAnOverlayEndingToday` pins that boundary.

### Debug Log
- Two fixture bugs, both in the test rather than the job. Repeated `insertOverride` calls reused ordinal 1 on the same bell schedule and hit the `(bell_schedule_id, ordinal)` unique index — fixed by deriving the next ordinal. And `isIdempotent` saw a sweep count of 2: the H2 instance uses `DB_CLOSE_DELAY=-1`, so it outlives each `@DirtiesContext` reload and earlier tests' overlays were still present. Since this job is cross-tenant by design it cannot filter them out, so the fixture now clears both temporary-schedule tables before each test.

### Completion Notes
- No WebSocket event on expiry, per the technical note ("No notification required for expiry").
- Expiring frees the timetable for a new overlay, because COVER-05's "only one active" rule keys on `status = 'ACTIVE'`; covered by `expiringFreesTheTimetableForANewActiveOverlay`.
- `./mvnw -o test -Dtest='TemporaryScheduleExpiryJobTest'` → 8 passed.
